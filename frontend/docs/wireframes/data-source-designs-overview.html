Data Source Configuration: UX Wireframe Suite

A comprehensive exploration of user experience patterns for configuring, parameterizing, and binding dynamic data sources in Sundance Forms Hub. Grounded in ADR #005 Strategy Pattern (Static, Scheduled, Webhook, Data Lake) and real-world form designer workflows.

⚙ 3 Distinct Design Paradigms

Each design addresses data source configuration from a distinct architectural and ergonomic perspective.

Design 1 • Focused Workflow

Drawer Wizard & Attribute Inspector

A contextual slide-over drawer that preserves the form builder context while walking the designer through type selection, endpoint/query specification, response extraction, and live dry-run testing.

  • ✓ 4 Type Selector Cards: Instant switching between Static, Scheduled, Webhook, and Data Lake.
  • ✓ Type-Specific Forms: Dynamic inputs for URL, headers, intervals, RequiredKeys, or SQL.
  • ✓ Live Test Bench: Real-time HTTP/SQL simulation showing raw JSON and normalized ILookup[] dropdown pills.
  • ✓ Zero Context Loss: Opens over the canvas and immediately updates the selected field.
▶ Launch Design 1 Prototype
Design 2 • Governance Studio

Master-Detail Reference Data Studio

A full-page dedicated studio (the "Reference Data" top tab) for managing tenant-wide reusable data sources with background ingestion metrics, cache expiration counters, and multi-form usage tracking.

  • ✓ Tenant Reusable Catalog: Master list of all sources with search, filters, and health badges.
  • ✓ Sync & Ingestion Monitoring: Track cache TTL, interval hours, and retry attempts.
  • ✓ Usage Auditing: View all forms and fields currently consuming the data source.
  • ✓ Ideal for Data Engineers: Best for centralizing corporate APIs and lakehouse queries.
▶ Launch Design 2 Prototype
Design 3 • Frictionless Inline

Field-Centric Inline Binding & Preview

Embeds data source selection and cascading parameter bindings directly inside the existing ObjectSettingsPanel with an interactive live dropdown preview on the canvas.

  • ✓ Cascading Field Lookups: Map webhook parameters to upstream form fields (e.g. Country → Facility).
  • ✓ Inline Mode Toggle: Instant switch between Static Manual Options and Connected Data Sources.
  • ✓ Live Dropdown Simulation: Test clicking and selecting dropdown items right on the canvas.
  • ✓ Fastest Form Building: Minimizes clicks for standard select and checkbox fields.
▶ Launch Design 3 Prototype
Design 4 • Architectural Decoupling

Dedicated /data-sources/ Studio & Read-Only Reference Panel

Aligns directly with routes/data-sources/index.tsx and CreateDataSourceDrawer.tsx: manages data sources at /data-sources/ and /data-sources/$dataSourceId while keeping the Form Designer's Reference Data panel strictly read-only & consumption-focused.

  • ✓ Production Route Alignment: Matches /data-sources/ with DataSourcesToolbar, CardList, and DataSourceCard.
  • ✓ Modal Drawer Creation: CreateDataSourceDrawer handles Name & Description, smoothly navigating to /data-sources/$dataSourceId.
  • ✓ Read-Only Reference Panel: Previews connected sources, parameters, and lookups with direct "Manage in Data Sources Studio ↗" links.
  • ✓ Zero Cross-Form Side Effects: Form designers cannot accidentally mutate shared tenant endpoints from within a form version.

🛠 Architectural Alignment (Sundance Backend & Frontend)

How each data source type maps to domain contracts defined in ADR #005 and DataSourcesService.

☰ Static Lookups

In-memory key-value pairs stored directly in form or tenant record. Zero network dependency.

Data: []*Lookup { label, value }
🕑 Scheduled Ingest

Background worker queries external API periodically and caches results locally with TTL.

IntervalHours, ExpirationDate, ValueField, LabelField
⚡ Webhook API

Real-time HTTP fetch on form interaction, parameterized by upstream field values.

URL, Headers, RequiredKeys[], ValueField, LabelField
🗃 Data Lake SQL

Direct BigQuery / Lakehouse SQL queries with parameter binding tokens (:param).

Catalog, Schema, Query, TimeoutMs, ValueCol, LabelCol

🚀 Recommended Implementation Strategy

How to deliver maximum user value incrementally within frontend/apps/forms.

Phase 1 • Immediate
Implement Design 3 + Design 1 Drawer Trigger

In ObjectSettingsPanel/settings/, create SelectElementSettings.tsx featuring Design 3's inline data source selector and parameter bindings. Clicking "+ Create / Edit Data Source" opens Design 1's slide-over drawer wizard. This gives form designers complete functionality immediately without disrupting existing navigation.

Phase 2 • Near-Term
Activate "Reference Data" Tab with Design 2 Master-Detail Studio

Add the Reference Data tab to the Form Designer header tabs in index.tsx, allowing tenant admins to manage corporate data sources globally, view cache expiration countdowns, and trigger manual ingestion sync jobs.
